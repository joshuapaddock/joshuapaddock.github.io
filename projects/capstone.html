Adaptive routing for LLM inference clusters

Expert placement and request routing for mixture-of-experts (MoE) LLM inference on a single 72-GPU rack. We measure expert skew, how unevenly a model's experts are used, and use it to decide where experts live and where requests go: a custom router that uses prefix-aware caching (SGLang / vLLM) to maximize GPU utilization under time-to-first-token (TTFT) and throughput targets.

Problem

Place experts and route requests so a 72-GPU rack stays busy while latency and throughput targets hold as load shifts.

Approach

Measure expert skew on real workloads, then route with a custom policy; routing is modelled as a stochastic control problem (a Markov decision process).

Status

In progress

Two expert-skew experiments running on 2× RTX A5500. Results will be posted as they come in.

01 Problem

Common load-balancing rules like least-loaded routing look at a single signal. Inference servers carry much more state: queued prefill and decode work, KV-cache occupancy, and replica capacity. Routing that ignores it can miss latency targets under bursty traffic.

02 Measuring expert skew

In an MoE model each token is sent to a few of many experts, and some experts get far more traffic than others. That skew decides how experts should be spread across GPUs. We're running two experiments on 2× NVIDIA RTX A5500:

  • Single pass: expert skew across one pass of SWE-bench inputs.
  • Multi-pass: expert skew across repeated passes over similar inputs.

The skew map drives expert allocation across a 72-GPU rack, and a custom routing algorithm that uses prefix-aware caching in SGLang or vLLM to maximize GPU utilization.
